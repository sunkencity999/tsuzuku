Four tables, **1,043 rows**: `data-a-d.ts` 288 · `data-e-j.ts` 251 · `data-k-m.ts` 264 · `data-n-z.ts` 240. `index.ts` owns the lookup: `normalizeLatin` (first word, NFD accent strip with ø / æ / œ / ß / ł / đ / þ / ð / ı folded, lower-cased, `a-z` and `-` only), `lookupName(table, input)` (a per-table `WeakMap` index, first row wins on a repeated key), `suggestName = lookupName(ALL_NAMES, …)`, `soundGuide(romaji)` / `soundGuideText` (the romaji fed to `imeStep` one character at a time and cut wherever the resolved katakana grows; `-` shown as ー; trailing pending romaji is the last syllable). The romaji is verified by `names.test.ts` over the REAL tables (31 tests): every key matches `/^[a-z][a-z-]*$/`, equals `normalizeLatin(key)`, is unique across `ALL_NAMES` and sits in its file's letter range; every kana is pure katakana (ァ-ヺ ー ・); every romaji is IME romaji and `finalizeIme(romaji, { katakana: true }) === kana`; `soundGuide(romaji)` partitions the romaji exactly and types back to the kana; a final ン is spelled with one `n` (the IME resolves it) and `nn` only before a vowel; each table is strictly ascending; `ALL_NAMES` is the four tables concatenated (≥ 500); smoke lookups (Christopher / christopher bradford → クリストファー, José → ホセ, Zoë → ゾーイ, Michael, sean, STEPHEN, Graham, Hugh, Chloé, Isla, Xavier; xyzzy → null; クリス → null — `normalizeLatin` strips non-Latin, so kana input never matches a row even though chris → クリス is one) and every row reachable through `suggestName(key)` and `suggestName('Key Smith')`.
